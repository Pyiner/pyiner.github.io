修复结论

本次真实 run_id: ar_af30525282fc49ecb5a9541ee7fe0870

这次修了什么

  • auto_research_verdict 已经成为 AutoResearch verifier 的主判定路径，不再依赖自由文本 JSON 作为主流程。
  • active verifier thread authorization 让 tool 调用不再要求自定义 header 每一跳都成功回放。
  • gateway 现在接受合法的 JSON-stringified verdict 数组字段，降低 provider 侧参数漂移造成的直接拒绝率。

这次真实验证到了什么

  • 五个 verify 线程全部通过 MCP tool 存下了结构化 verdict，整个 run 完整跑满 5 轮。
  • 第 1 轮仍然出现了一次坏掉的字符串化 dimension_scores，但同一 verify 线程随即用正确数组重试成功，主循环没有中断。
  • 后续第 2 到第 5 轮都是一次成功提交，最终 best score 从 6.8 持续提升到 8.3。
一句话结论

这次修复把 AutoResearch 的 verifier 主路径从“可能被自由文本 JSON 绊倒”收成了“以 MCP tool 为主、授权可兜底、参数漂移可容忍、同轮还能自愈重试”的状态。

仍然值得继续收口的点

  • 第 1 轮的第一次 tool call 仍然会偶发坏掉，说明 provider 侧还会产出 malformed stringified array。
  • 当前链路已经能自愈，但下一步仍值得继续压低“首跳失败、二跳成功”的发生率。
  • 这页的价值就在于，它不是假设修好了，而是把修复后的真实残余问题也一并展示出来。

Definition of Done

  1. 只输出 6 行，且前缀顺序固定为：标题：、核心观点：、证据一：、证据二：、证据三：、结尾：。
  2. 标题必须同时包含 AutoResearch 和“开放性问题”。
  3. 核心观点必须同时包含“对抗式收敛”、Worker、Verifier，并说明两者如何互相施压。
  4. 证据一必须引用 [docs/auto-research.md]，说明它是面向用户的 harness 功能，或说明用户提供 Task + Definition。
  5. 证据二必须引用 [docs/architecture.md]，并明确提到 garybot-gateway 或 garybot-router 在流程中的角色。
  6. 证据三必须引用 [docs/agent/runtime-map.md]，并明确提到 desktop/gary-desktop，或说明 verifier verdict 通过 MCP tool 提交。
  7. 结尾必须同时包含“优化型任务”和“越跑越好”，全文必须是中文，不允许额外说明、分隔线或 markdown 列表。

为什么这个命题适合 Demo

  • 它是明显的开放性、优化型任务，不是一眼就有唯一正确答案的封闭题。
  • 结构约束很硬，内容空间又足够大，天然适合演示“格式、叙事、卖点”之间的反复拉扯。
  • 每轮提升都能被 verifier 讲清楚，所以这不是“润色几次”，而是“每轮都知道为什么变好”。
  • 最终没有一轮神奇满分，反而更适合说明 AutoResearch 的真实价值是“持续逼近更优”。

为什么这很适合讲开放题

这不是一道“答对就结束”的题，而是一次可持续优化的开放题。 每一轮都不是简单改字，而是在新的高水位上继续被 Verifier 逼着补剩余短板。

现场讲解抓手

  • 先讲工程修复：verdict 从自由文本收成 MCP tool。
  • 再讲产品价值：五轮里每次都能看懂它为什么变得更好。
  • 最后讲剩余问题：连第 5 轮都还可以更好，这正是开放题的本质。

AutoResearch 最适合开放性、优化型任务。因为这类任务没有一眼就写对的唯一答案， 但每一轮都可以在上一轮基础上再好一点。Worker 不断试，Verifier 不断挑刺， 最后得到的不是“看起来差不多”，而是一个可解释、可追溯、可持续优化的收敛过程。

这次实验真正证明了什么

  • 工程上：verifier verdict 主链路已经切到 MCP tool，5 个 verify 线程全部成功存下结构化 verdict。
  • 产品上：在开放性卡片任务里，5 轮分数从 6.8 稳定提升到 8.3，每轮都能解释“为什么更好”。
  • 系统上：第 1 轮即使出现了一次坏掉的字符串化参数，也能在同轮自愈重试，整个 run 没有因为 verdict 链路而中断。
  • 后续上：下一步不是“修大 bug”，而是继续压低首跳 malformed tool args 的发生率，并把最终卡片再推向更轻、更快扫读的表达。
